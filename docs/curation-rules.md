# 收录规则（Curation rules）

规则从 v5–v7 累积而来，优先级从上到下。拿不准就不收，不写「待找视频」的占位卡。

## 1. 趋势：核心过滤（三条同时满足）
1. **真火（viral）**：代表视频本身是爆款，用平台数字说话（通常 ≥ 百万播放或明显的高分享率）。
2. **被大量二创（remixable）**：很多不同账号在模仿 / 二创，有可复用的模板、音频、格式、角色或梗台词。只有原作者自己的系列不算。
3. **可迁移（transferable）**：能变成 C 端社交、创作、直播或场景创意设计产品里的一个具体功能或玩法，写进 `kx`。

### 直接排除
- 一次性单条视频：开箱、品牌 Short、长视频挑战（如 MrBeast）、单个制作人的整活。
- 没有经典梗或表演的明星采访 / 谈话片段。
- 生活技巧、育儿技巧类。
- 核心用法有伤害性、无法迁移的（例：用 AI 幽灵滤镜吓孩子）。
- 「X 自动生成的趋势摘要」、AI 聚合页、没有视频的话题。它们只能当线索，不能当证据。
- v7 据此删掉：What iPad?、Tom Holland 采访梗、孩子咳嗽、神秘包裹、Red Bull 悬崖跳水、MrBeast、放屁编曲、鬼脸情侣、Congo Basin、Mebaje、万圣节小猫走秀、幽灵滤镜。

## 2. 证据规则（硬性）
1. **代表视频**：至少一条公开可播放的爆款视频（TikTok / YouTube / Instagram / X / B站），嵌入或原链接能打开、没被删。
2. **平台数字**：该视频在平台上显示的播放 / 赞 / 分享（至少一项，TikTok 必须有播放和分享）。只用平台页面或其镜像计数；用 FlashCounts、ChartsList 这类读 YouTube 数据的站，在 `st.via` 注明。文章里转述的「全网 X 亿」只能放 `vir`（补充数据），不能当主数据。
3. **新鲜度**：走红在约 6 周内。代表视频可以更早，但 `hot` 要写清楚近期何时走红；超过 6 周且已退潮的删除。
- 拿不准的点写进 `v`（页面显示「注」），但三条硬规则不能用 `v` 豁免。
- **永远不编造**链接、数字、日期。读不到就写读不到。
- **第三方数字**（Jump on the Trend、MakeViral、TrendSwap、Zooop、报道转述）必须在说明里写「第三方 + 读数日期」。
- 抖音数字从云端读不到：抖音原作写进 `v`，代表视频和数字改用 B站转发 / 二创，并写明。

## 3. 每张卡必须有的字段（页面上看得到）
- **来源日期**（`sd`）：代表视频发布日期。
- **走红时间**（`hot` 文本 + `hs` 日期）。
- **数据采集日期**（`st.rd`）：数字是哪天读的。
- **可借鉴**（`kx`）：一句、具体，说清这个梗怎么变成社交 / 创作 / 直播产品里的一个功能或玩法。例：「上传宠物照片 + 选一支舞」的动作迁移模板，生成后一键发起同款挑战。不写空话（如「可以借鉴其传播逻辑」）。
- **二创证据**（`rx`）：
  - 优先量化：音频 / 话题 / 模板下的视频数或总播放（TikTok 音频页、话题页通常读不到数字，只能用第三方并标注）。
  - 否则放 **2–3 条不同账号**的二创链接，说明写成 `@账号 · 7.9 万 播放 · 10-10`（`refresh_tiktok.py` 会按这个格式刷新播放数）。
  - 找不到真实二创的，整条删除，不留空 `rx`。
- **传播指数**（页面现算，不存）：`60 × min(log10(播放) ÷ 8, 1) + 40 × min(分享 ÷ 播放 ÷ 10%, 1)`。1 亿播放记满 60，分享率 10% 记满 40；缺播放或分享就不显示。

## 4. 范围与数量
- 海外为主（TikTok / IG / YouTube Shorts / X），实时信息流目标 20–30 条。
- 国内条目少量。特别值得做产品借鉴的放主信息流（不写 `cn`，如大长今、AI 拟人），其余放折叠的「国内」区（`cn:1`，最多 2–3 条）。同样走所有规则。
- 素材来源：Lightreel 周报、newengen、Ramdam、Jump on the Trend、Know Your Meme、TrendSwap、NBC / Yahoo / USA Today 等报道里的原链接；YouTube Shorts 看 ChartsList；Miya 的截图（`data/seeds.json`）。

## 5. 置顶（pin）
- 当前顺序：1 小猫举剑（knight）、2 风扇转场换装（fan）、3 LISA 水瓶舞（sawadika）、4 大长今（janggeum）、5 AI 拟人（aimoe）。
- 置顶由 Miya 指定。AI 不自行新增置顶；置顶卡退潮或不再满足规则时，去掉 `pin` 或删卡，并在报告里说明。
- 页面先排置顶，其余按排序按钮排，排序只作用于置顶以下。

## 6. GitHub 区（Skills / 项目）
- 门槛：**星数 ≥ 10k**，用 `gh api repos/<owner>/<repo> --jq .stargazers_count` 实测，不信截图或文章。
- 两类：
  - **Skill**（`t:"skill"`）：给 Claude Code / Codex 等 Agent 用的技能包、CLAUDE.md、技能市场。来源：`gh api search/repositories`，topic `claude-skills`、`agent-skills`、`claude-code-skills`，名称含 skill(s)、README 含 SKILL.md 的高星仓库。
  - **项目 / 工具**（`t:"tool"`）：和 AI、创作相关、影响 AI 产品形态的热门开源项目（Agent 框架、AI 视觉 / 视频工作台、设计系统、画布、自动化）。
- 分类只用：**工程/Agent、设计、美学、动效·视频、玩法、效率**。不设「官方」「精选目录」；awesome 列表类仓库不收。
- 每张卡有仓库链接 + 一张图：优先 README 图，其次 GitHub 社交预览图，都没有就用 `dg:["输入","过程","输出"]` 示意。图 640×400 WebP；横幅类长图（宽高比 > 1.9）不裁，用边缘色补边。
- 规模约 40–50 张，宁缺毋滥；对 PM 求职直接有用的（如 pm-skills、career-ops）优先。

## 7. 设计规则（改模板时）
- 深色高对比文字：正文 `#1f1f1f`、次级 `#4a4a4a`、三级 `#5c5c5c`。不要浅灰小字。
- 趋势卡：左边视频（可播放），右边分析；显示来源日期和走红时间。
- 设计师水准、留白，不要信息堆砌。
- 文案简洁具体；不写填充句、自我评价、「本站 / 我们发现」之类的元话语。

## 8. 周报流程（每周五）
1. **刷新实时信息流**：按 `docs/refresh-playbook.md` 跑脚本刷新数字、查死链；按 `docs/taste-profile.md` 找新候选，过本规则后加进 `data/live.json`。
2. **定稿本周**：把本期 JSON 和 `weeks/index.json` 里的 `status` 改成 `"已定稿"`，补全最终 `change`。页面在 `end` 当天 23:59（UTC+8）后也会自动显示「已定稿」。定稿后不再改该期。
3. **开下一期**：新建 `weeks/<YYYY>-W<ww>.json`（可复制上一期改），`range` 如 `2026-11-02 ~ 11-06`，`start`/`end` 为周一和周五，`status:"本周更新中"`；在 `weeks/index.json` 的 `issues` 最前面插入。
   - `patterns`：4–6 条 `{t, d, ex:[2–4 个 k]}`，只能引用仍在 `live.json` 里的卡。
   - `change`：`{up:[[文字,k]], down:[[文字,k]], note}`，写本周什么在升温 / 降温，要有依据。
   - `log`：数组，最新一行在前，如「10-30 更新：新增 …；移除 …（原因）」。
   - `cards`：`{k:{n, s: 短标题}}`；`thumbs`：从 `assets/live/<k>.webp` 缩到 240×427 放进 `assets/weeks/<id>/`。
4. 从实时里删掉某条时，同步从当期 `patterns`、`change`、`cards`、`thumbs` 删掉并删缩略图（已定稿的往期不动）。
5. 预览、提交、推送、确认线上（见 AGENTS.md）。
